# RELICA STORY

RELICA 소개 웹사이트와 네 멤버를 선택해 플레이하는 Phaser 디펜스 게임입니다. 멤버는 기준 시트를 참고해 생성한 투명 SD 픽셀 이미지이며, 배경은 사용자가 제공한 멤버별 환경 레퍼런스를 참고해 생성한 픽셀 아트입니다. 적은 임시 코드 아트입니다.

## 실행

Node.js 20 이상에서 프로젝트 폴더 안에서 실행합니다.

```text
npm run dev
```

http://127.0.0.1:4173/ → 입장하기 → 미니 게임 → 멤버와 모드 선택 → 게임 시작.
Phaser 3.90.0 배포 파일과 라이선스는 assets/vendor/에 들어 있으므로 플레이 중 외부 CDN 연결은 필요하지 않습니다.

## 현재 구현

- 입장 화면, 홈, 그룹·멤버 소개, PC·모바일 메뉴
- 이메일 회원가입·로그인·로그아웃·비밀번호 재설정, Supabase 연동 코드. 실제 서비스는 public-config.js 설정 및 supabase/schema.sql 실행 후 활성화됩니다. 사용자가 제공한 공개 키를 적용했습니다. 실제 API에서 이메일 가입/확인 활성화와 기록 테이블·저장 함수 생성을 확인했습니다. 비로그인 테이블/함수 호출은 권한 오류로 차단됩니다. 실제 사용자 로그인 후 저장·복원은 아직 별도 확인이 필요합니다.
- 네 멤버의 자동 발사와 수동/자동 조준 전환
- 공용 강화와 현재 멤버 전용 강화 선택, 상한 및 화살 배타 선택
- 스테이지 체력 30, 무한 체력 50, 적당 피해 1, 스테이지 클리어 회복 5
- 체력 비례 경험치, 1×/2×, 스테이지 대기·계속하기, 결과 및 로컬 최고 기록
- 스크롤 중 진행, 백그라운드 콜백 지연 후 따라잡기. 강화 선택/대기에서는 멈춥니다.

| 멤버 | 공격력 | 기본 발사 간격 | 투사체 속도 | 주요 전용 효과 |
|---|---:|---:|---:|---|
| 아렌 | 40 | 0.75초 | 600 | 검기 범위, 근거리·원거리 강화 |
| 엘리아 | 40 | 0.6초 | 700 | 다중 발사, 관통 또는 튕김, 폭발 |
| 셀렌 | 30 | 0.8초 | 650 | 체인·얼음·화상 |
| 누아르 | 25 | 0.55초 | 750 | 벽 반사, 다중 발사·독·전기 |

## 스킬 설명 및 수치 수정

현재 기준은 루트의 스킬_설명과_수치_수정용.txt입니다. 스킬_정리/에는 공용·아렌·엘리아·셀렌·누아르 분리본이 있습니다. 사용자 수정 원본은 docs/history/skill-originals/스킬_메모_사용자원본_2026-10-20.txt 등에 보관했습니다.

메모장 파일을 수정해 대화에 전달하면 설명과 실제 계산을 함께 수정합니다. 런타임에서 메모장 파일을 자동으로 읽거나 변경 사항을 적용하지 않습니다. 통합본/분리본도 자동 동기화하지 않습니다.

파일의 [임시] 표시는 사용자 원문에 범위 등의 숫자가 없어서 테스트용으로 넣은 값입니다. 이 값은 combat.js의 TUNING에서 관리합니다. 확인된 수치와 구분해 검토합니다.

강화가 모두 상한에 도달하면 남은 유효 강화만 표시합니다. 모든 유한 강화를 마치면 공격력 강화 한 개가 남습니다.

## 코드와 데이터

- combat.js: 멤버별 공격·강화·상태이상 및 전투 시계
- game.js: Phaser 화면, 조작, UI와 기록 저장
- model.js: 기존 브랜드의 멤버 소개와 팔레트, 클래스 테스트
- account.js / auth-ui.js: 인증 SDK 연결, 계정 분리, 기록 병합, 로그인 UI
- public-config.js: 브라우저 공개 설정(URL과 Publishable key만)
- supabase/schema.sql: 사용자별 RLS와 원자적 기록 병합 함수
- index.html / styles.css / app.js: 웹 화면과 메뉴
- server.cjs: 웹 자산만 제공하는 로컬 미리보기 서버
- docs/history/asset-notes.md: 원본 브랜드 자료와 임시 배경 생성 기록
- docs/history/game-plan.md / docs/history/skill-plan.md: 이전 결정과 최신 메모 위치

게스트 테스트·기록은 localStorage의 relica.story.guest.v2, 로그인 계정의 오프라인 임시본은 relica.story.account.<사용자ID>.v1로 분리합니다. 예전 기록/테스트 키는 처음 읽을 때 가져옵니다. 로그인하면 게스트 데이터를 계정별 공간으로 옮겨 서버와 합칩니다. 최고 기록은 큰 값, 테스트는 최신 시각의 결과를 유지합니다. 현재 전투는 새로고침·브라우저 종료·탭 폐기 후 복원하지 않습니다. GitHub/Vercel 배포는 진행하지 않았습니다.

## 클래스 테스트

8문항의 취향 테스트 → 멤버별 결과 카드 → 추천 멤버가 선택된 게임 화면으로 이어집니다. 문항과 결과 문구는 기존 성격 설정을 바탕으로 한 초안이며 model.js의 quizQuestions/quizProfiles에서 수정합니다. 각 답변은 해당 멤버에 1점이고, 동점일 때는 공동 1위 중 가장 최근 선택한 멤버를 추천합니다. 확률이나 심리 진단 점수를 뜻하지 않습니다.

완료 결과의 응답·버전·완료 시각을 게스트/계정별 공간에 저장하고 다시 계산해 복원합니다. 같은 브라우저에서 닫았다 열어도 남지만, 사이트 데이터 삭제·시크릿 모드 종료 시에는 사라질 수 있습니다. 도메인/포트가 다르면 별도 저장입니다. 진행 중 응답은 페이지 이동 동안만 유지하고 새로고침 뒤에는 완료한 마지막 결과를 보여줍니다. 다시 테스트하기를 눌러도 새 결과를 완료하기 전까지 마지막 저장 결과는 유지합니다. 저장을 차단해도 현재 화면에서 테스트를 할 수 있습니다. 진행 중인 게임은 테스트 결과로 멤버를 바꾸지 않으며, 종료 후 다시 연결하면 추천 멤버를 선택합니다.

검증: node tests/quiz-browser.cjs (답변·이전 질문·복원·게임 연결·진행 중 전투 유지·모바일·저장 차단). 게임 수치는 이번 작업에서 변경하지 않았습니다.

## Supabase 연결

루트의 Supabase_연결_안내.txt에 설정 순서를 정리했습니다. 프로젝트 URL/공개 키는 적용했습니다. 사용자 대시보드에서 SQL 실행은 완료됐고, 복귀 URL·메일 발송 설정 및 실제 사용자 인증 확인이 남아 있습니다. 인증 SDK는 assets/vendor/supabase-2.95.3/에 버전과 라이선스를 고정해 두었습니다. API 키가 없으면 게스트 기능은 동작하고 로그인 요청은 전송하지 않습니다. Secret/service_role 키는 브라우저 코드에 넣지 않습니다.

비밀번호는 SDK가 HTTPS로 Supabase Auth에 전송하며 앱이 보관하지 않습니다. SDK가 로그인 유지용 토큰을 브라우저에 저장하므로 공용 PC에서는 로그아웃해야 합니다. 인증 콜백에서 DB를 직접 호출하지 않고 다음 작업으로 넘겨 SDK 잠금 충돌을 피합니다. 비밀번호 재설정은 PKCE와 별도의 복귀 쿼리(relica_auth=recovery)를 사용합니다. 이 쿼리는 화면 전환용이고, 비밀번호 변경 권한은 Supabase 세션으로 검증합니다.

통신 실패 시 계정별 캐시를 유지하며 온라인 복귀·다음 로그인·내 계정의 다시 동기화로 재시도합니다. 계정 변경 중 도착한 이전 요청은 현재 화면을 덮지 않습니다. 로그인/로그아웃 도중 진행 중인 전투는 시작한 저장 공간에 결과를 남깁니다. 계정 전환 후 이전 계정 전투가 끝났다면 해당 계정으로 다시 로그인했을 때 서버에 반영합니다. 다중 기기 병합은 DB 함수에서 원자적으로 처리합니다. 테스트 결과 충돌은 클라이언트 완료 시각 기준이므로 기기 시계를 바꾸면 순서가 달라질 수 있습니다.

RLS는 본인 기록만 허용합니다. 클라이언트가 점수를 제출하는 개인 저장 기능이며, 부정행위 방지 순위표는 포함하지 않습니다. Supabase 실제 프로젝트에서 메일 발송·요청 제한·2계정 RLS 검증은 연결 후 추가 확인해야 합니다. 로컬 검증은 실제 SDK+대체 HTTP 응답, 실제 PostgreSQL(PGlite)의 SQL/RLS 검사입니다.

## 픽셀 전투 표현과 효과음 (2026-10-21)

assets/game-presentation.js는 멤버별 머리·의상·무기, 임시 적 3종, 숲·유적·돌바닥의 픽셀 배경을 Phaser Graphics로 그립니다. 원본 브랜드 이미지를 수정하거나 추가 공식 설정을 만든 것은 아닙니다. 전투 판정·수치·경험치·강화는 combat.js를 그대로 사용합니다.

아렌은 와인색 긴 머리·코트·검/방패, 엘리아는 샌드블론드 머리·아이보리/그린·활, 셀렌은 짙은 보라 머리·긴 로브·지팡이, 누아르는 딥퍼플/블랙·짧은 재킷·단검으로 구별합니다. 몬스터 외형별 능력치는 아래 최신 항목을 따릅니다. 동작 줄이기 설정을 따릅니다.

효과음은 외부 음원을 쓰지 않고 Web Audio의 짧은 합성음으로 만듭니다. 공격·처치·벽 피해·레벨업·스테이지 클리어·종료에 간단한 소리가 나며 배경음악은 없습니다. 기본 음소거, relica.story.sound.v1에 켬/끔을 저장합니다. 저장된 켬 설정이 있어도 사용자 클릭 전에 AudioContext를 만들거나 재생하지 않습니다. 숨김 탭·메뉴·모달·일시정지에서는 소리를 차단합니다. 최소화 중 경과시간을 따라잡을 때 지나간 소리를 몰아서 재생하지 않습니다.

## 멤버 SD 픽셀 이미지 (2026-10-21)

RELICA 멤버 기준 시트 4장을 실제 확인하고 built-in image_gen으로 귀여운 2~2.5등신 SD 픽셀 캐릭터를 각각 생성했습니다. assets/characters/의 *-sd-v1.png 네 파일은 생성 원본을 그대로 보관한 투명 PNG입니다. 원본 브랜드 자료는 수정하지 않았습니다. assets/characters/sd-frames.js에 미리 기록한 투명 영역 경계로 렌더링 프레임만 맞춥니다. 게임 실행 중 캔버스 픽셀을 읽지 않으며 PNG 자체를 자르거나 리샘플링하지 않습니다. 게임 안에서는 선명한 픽셀 표시로 축소하며, 네 멤버의 발 위치와 표시 높이를 맞춥니다. 현재 정지 포즈 1장씩이며 호흡 표현은 위치 이동입니다. 별도 공격 애니메이션 프레임은 아직 없습니다.

원본 역할·생성 방식·전체 프롬프트는 docs/art/sd-character-prompts.md에 보관했습니다. 기준 시트의 긴 머리·의상·장식·무기를 SD 비율에 맞게 단순화한 표현입니다. 스킬 수치와 판정은 바꾸지 않았습니다.

RELICA 폴더와 ZIP 항목 이름을 확인했지만 멤버별 장소의 배경 레퍼런스 이미지는 찾지 못했습니다. 사용자 요청에 따라 새 멤버 배경은 생성하지 않고, 아렌:고지대 성채 / 엘리아:고대 숲 / 셀렌:호숫가 초원 / 누아르:달빛 주거지의 레퍼런스를 요청했습니다. 이 대기 상태는 아래 멤버별 배경 적용 항목으로 대체됐습니다.

검증: node tests/sd-art-browser.cjs — 네 투명 PNG의 실제 로드·멤버별 게임 표시·전투 시작·모바일 레이아웃.

## 멤버별 배경 적용 (2026-10-21, 이전 배경 대기 안내보다 우선)

사용자가 첨부한 환경 레퍼런스 4장을 실제 열어 확인한 뒤 built-in image_gen으로 멤버별 픽셀 배경을 생성했습니다. 아렌(사용자 메시지의 엘렌)은 황야·성채, 엘리아는 숲, 셀렌은 호수, 누아르는 중세 밤 도심입니다. 새 멤버나 장소 이름은 정하지 않았습니다. 주요 풍경은 상단·가장자리에 두고 전투 영역은 넓고 평평하게 구성했습니다. 멤버를 선택하면 배경이 바뀌며, 게임 시작·종료·재시작에서도 선택 배경을 유지합니다.

원본 레퍼런스 사본은 docs/art/references/, 최종 생성 PNG는 assets/backgrounds/*-background-v1.png입니다. 이미지는 불투명 정지 배경이고 원본 PNG를 그대로 보관합니다. 실제 렌더링에서 게임 크기에 맞춥니다. 전체 프롬프트와 생성 방식은 docs/art/member-background-prompts.md를 참고하세요. 상단 설명용 어두운 띠, 약한 전체 음영과 이름 윤곽선은 가독성을 위한 게임 렌더링입니다.

기존 SD 캐릭터 이미지·입장 화면·게임 수치·타격 판정은 바꾸지 않았습니다. 이미지 로드 실패 시 코드로 그린 기존 배경을 사용합니다. 검증: node tests/background-browser.cjs — 4개 배경의 실제 픽셀 변화, 멤버별 이름 표시, 전투 실행, 모바일 레이아웃.

## index.html 직접 열기 수정 (2026-10-21)

폴더의 index.html을 더블클릭해 file:// 주소로 열어도 게임의 SD 캐릭터 4종과 멤버별 배경 4종이 표시됩니다. Phaser 기본 XHR 이미지 로더는 파일 주소에서 CORS로 차단되므로 HTMLImageElement 로더를 사용하고 crossOrigin을 null로 지정했습니다. 파일 이미지가 그려진 캔버스는 보안상 픽셀을 읽을 수 없으므로, 기존 원본 PNG의 알파 경계는 sd-frames.js에 미리 기록했습니다. PNG가 교체되면 이 표시 정보도 다시 계산해야 합니다. 브라우저 보안 설정이나 로컬 파일 접근 제한을 끄지 않습니다.

검증: node tests/file-browser.cjs — 실제 file:// index.html에서 네 멤버/배경 로드, 전투, 테스트→게임 연결, 모바일, 브라우저 오류 없음. 이 검사는 서버 URL로 대체하지 않습니다. 실제 인증 메일 링크와 계정 사용 검증에는 로컬 웹 서버 또는 배포된 웹 주소를 사용합니다.

## 몬스터 외형별 능력치 (2026-10-21)

기존 픽셀 외형 3종에 임시 능력치를 연결했습니다. 결정형(파랑)은 체력 34/이동속도 26, 박쥐형(보라)은 체력 22/이동속도 38, 슬라임형(초록)은 체력 56/이동속도 18입니다. 두 모드에서 같은 외형은 같은 기본 능력치를 사용합니다. 난이도 단계에 따라 체력은 기본값 × (1 + 0.22 × 단계)를 반올림하고, 속도는 기본값 + min(단계, 30) × 1.3입니다. 벽 도달 피해는 모두 1이며, 처치 경험치는 실제 최대 체력 / 34를 유지합니다. 원본 브랜드 설정과 무관한 게임용 임시 몬스터입니다.
